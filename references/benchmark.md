# AIS-bench、coding质量与矩阵口径

## 先固定协议

冻结模型/量化/image digest、实际配置、题库与tokenizer hash、采样/推理策略、缓存条件、输出策略、并发模型、请求数、超时、重试、判分器版本。时间预算变化可分批完成，但不能暗中删掉原矩阵或把2K smoke称为长上下文测试。

开始新测试前问清业务场景、并发范围、输入范围、输出策略、质量/性能目标、冷/热模式、请求数/重复次数与总时限。先展开并向用户确认每个档位与总格数，不把范围理解为只测端点。用户给了具体档位就严格使用，不替换成默认阶梯。

并发范围的默认档位为1、4、8、16、32、64及后续翻倍值；输入按Ktoken翻倍。范围内取这些档位，并保留用户给出的范围端点；用户明确要求C2、C48等则纳入确认列表。K=1024 tokens，不能以字符数代替。每一输入都跑每一并发，即笛卡尔积。

示例：C1–64、8K–256K → `[1,4,8,16,32,64]` × `[8,16,32,64,128,256]K` = **36格/配置/缓存模式**。两个配置为72格；每格重复3次为216次格执行，不是新增216种场景。可离线运行 `python scripts/build_matrix_plan.py --concurrency-range 1 64 --input-k-range 8 256` 核验；脚本位置相对本技能根目录。

边界容量测试（如近1M）单独确认逐级并发和停止条件。异常停止后，余格保留为未运行/因停止跳过，不宣称矩阵全部完成。若预计超时，先请用户选择缩减范围/重复数或延长时间，不擅自只测C1和最大C。

“1M”默认需明确为总窗口1,048,576，而非1M输入再加输出。分别记录总窗口、目标输入、服务实测input和output。自然输出需要输入之后留有空间；例如1,015,808输入预留32,768空间，不等于设置API输出上限。`max_model_len`设置成功不证明并发容量或模型实际长上下文质量。

coding默认自然完整输出，先向用户确认输出策略。用户要求不人为限制输出时，请求省略所有 max_tokens/max_completion_tokens/max_new_tokens，包括extra_body；还需核对AIS、代理、服务器默认是否隐式限长。自然EOS、完整答案、推理均保留；运行时间上限可用于保护，但超时须标为未完成。固定长度/ignore_eos是另一种性能工作负载，分开报告，不能直接作为自然coding的MTP A/B。

## LiteLLM 与 AIS 原生证据

- 正式请求走用户确认的入口（如LiteLLM）。精确核对model alias到目标服务；在授权的测试路由上禁用 fallback/retry，不能擅自影响所有业务路由。记录请求配置与实际观测后端/重试证据，缺失字段写unknown而非0。
- 直连只可用于已授权的诊断，并独立标记；不能用直连成绩冒充LiteLLM成绩。任何fallback污染结果不可作为目标模型基线。
- 采用实际AIS-bench安装版本的受支持数据集/适配接口。附加流事件采集器可补指标，但不把自写HTTP循环贴成AIS原生结果。
- 保存native配置、JSONL、summary、stream sidecar、request UUID映射及time_points引用的SQLite DB。仅带summary不足以复核时序。
- 请求记录保留：模型/后端、HTTP状态、开始/首生成/首答案/末生成/结束、usage、finish reason、DONE、重试、错误、输出与判分。失败也保留已观察到的usage/finish/timing，不能丢掉后再推算。

## 性能测量

使用客户端单调时钟算时长，UTC用于跨日志对齐。一次格内请求用UUID一对一join；校验expected/started/ended/success/failed/incomplete，拒绝重复和孤立事件。精确输入用实际tokenizer及chat template校准，并与服务usage核对。

| 指标 | 定义与注意事项 |
|---|---|
| TTFT | 请求发出到首个非空生成内容，包含reasoning，不包含空role事件；含网络、排队和prefill |
| 首个答案时间 | 到首次非空正式answer，和TTFT分开；只有推理时可缺失 |
| 平均有效TPOT | `(末生成时间-首生成时间)/(实际completion_tokens-1)`，秒转毫秒；token≤1或usage缺失则n.a. |
| 单请求decode TPS | TPOT秒值的倒数；输出计数包含推理，避免再次累加已经含在completion中的reasoning |
| 整批完成输出TPS | 所有成功完成请求的输出token之和 / 整格wall time，包含失败等待及收尾；不是并发×单请求TPS中位数 |
| 并发 | 分开记录配置C、按请求区间重建的峰值/平均在途、服务running/waiting |
| P50/P95/P99 | 说明有效样本数、插值方法、是否仅成功请求；旁边呈现失败率，小样本尾分位不作稳态SLA证明 |

MTP可能每个SSE chunk带多个token：chunk数不是token数，chunk间隔不是逐token ITL。客户端平均有效TPOT不是完整的硬件逐token轨迹。

固定长度传输通过不等于完整答案；完整答案不等于题目正确；HTTP200/DONE不抵消usage校准错误或截断。部分成功格的延迟只说明成功子集，不能宣称整格SLO达标。

## 缓存与decode侧重点

- coding应替换原矩阵的workload，不额外只跑短输入任务。保持长输入，生成实际代码/SQL和较长自然输出；不要抑制推理或截断输出来提高TPS。
- 冷/热分开。冷测使用独立prefix namespace并精确重校准；热测采用共享上下文+独立任务后缀，记录预热请求数和全部预热成本。
- 98%指推理引擎的输入前缀/KV缓存，不是LiteLLM或网关直接复用完整回答。正式测试路由关闭响应结果缓存（在授权范围内），确认实际发生decode，避免把缓存返回速度算作模型性能。
- 热测需所有实际DP副本覆盖，采集同cohort、无其他流量区间的原生cached-input与total-input增量，校验counter reset和来源一致性。命中率以token为分母，不能用请求命中或lookup计数冒充。
- **coding热缓存门槛为≥98%。** 先做有上限的预热并验证所有副本覆盖；测量区间结束后再次用原生token计数核验真实命中率。未达标/缺计数标“缓存条件未满足/不可验证”，保留实际结果，不作为达标coding热基线。不得靠无限预热、缩掉任务后缀、伪造98%或改题来过关；说明原因后再决定修复/重试。预热失败不等同正式容量失败；冷请求也不能承诺热缓存TTFT。
- 暖机、诊断、正式格单独计时。还要说明累计暖机成本，避免失败暖机成本消失。相同缓存准备才可比较配置。

## 客户智力对比与 SWE

先区分客户功能场景与官方SWE-bench。用户所说“中等SWE”须由题集ID/版本/难度筛选/固定manifest定义，不虚构官方“中级”标准。

根据客户提供的每个业务场景选择 **5–10道不同的中等难度、短时题目**，时间紧默认提议5道、希望增加覆盖提议10道，由用户确认。预先说明难度依据（需若干推理/转换步骤、有边界条件，但不依赖大型仓库/漫长构建）和单题/全套预计耗时。先用题库元数据或隔离校验估时，不消耗未经授权的模型调用。不能用同题重复次数充题数；例如5类×5题=25道，5类×10题=50道。

保持两模型相同题目、采样/推理、工具、时限与评分器；执行顺序及服务切换先确认。以下t1–t5只是客户场景示例，不默认套给所有客户：

| 类型 | 验证方式 |
|---|---|
| t1 Oracle→ANSI/SQLite | 覆盖NVL、DECODE、ROWNUM、outer join (+)；在SQLite比较行、列、顺序和NULL语义 |
| t2 Python→SQL | 将聚合、累计、百分比变化循环转为单条分析SQL/window函数，对比原程序固定样例输出 |
| t3 旧Python→现代Python | 保留行为，预先固定20个含边界/异常的测试，不只看语法或风格 |
| t4 对账代码找bug | 已知注入缺陷与诱饵，按独立缺陷ID计算recall、precision、假阳性，不重复记同一缺陷 |
| t5 SQL审查 | 真问题与诱饵清单，报告recall、precision和假阳性，不能仅按回答长度打分 |

正确率先由确定性测试/金标判分，不能让被测模型自评。生成代码在隔离沙箱执行：无生产凭据、无生产目录挂载、限CPU/内存/时间、按需禁网；SQL不连接生产库。

SWE要保留原repo/base commit、instance ID、agent轨迹、最终patch、官方grader日志与resolved结果；推理和grader分阶段续跑。部分已评分不是全套得分。两模型输入/模板/工具一致性需核实；无有效基线模型结果就明确比较尚未完成。

质量门槛按同题配对结果判断：pass/recall/precision不可下降、假阳性不可增加等由用户确认。不因少量样本的高分宣称统计显著或普遍编程能力更强。

## 终止后自动生成Excel

保留配置、card数、框架、版本、cache、output policy、suite/test phase维度，不能跨维度混算。每格标success/total、异常、实际输入/输出长度及指标。

在启动负载前完成汇总/Excel生成脚本，将其接在测试器的终止处理阶段（成功、失败、时间到或用户停止均生成对应完整/部分报告）。恢复后的报告由封存原始数据可重建；不需要用户再次要求Excel。生成失败须留下错误状态，由定时任务通知，不静默当作交付完成。

每个不同配置（模型/卡数/TP-DP/PD/MTP/batch/图模式等）独立sheet。列为输入，行为并发；同sheet各指标独立矩阵，冷/热或不同输出策略分区或分sheet，不能混算。sheet使用配置短名，附完整参数映射。

必含矩阵：TTFT P50/P95、TPOT P50/P95、单请求decode TPS、整批完成输出TPS、NPU计算利用率、HBM占用率、原生token缓存命中率、成功/总请求和错误/未完成状态。资源定义：

- NPU利用率：注明实际counter名称；对齐正式decode区间，按每卡有效采样时长加权，再给所有参与卡均值及最忙卡值。另列采样覆盖率、缺失卡，不能把采集机器CPU利用率替代。
- HBM占用率：每卡used/total，给decode区间时间加权均值和峰值矩阵；与HBM带宽利用率严格分开。若硬件提供带宽counter，可另加带宽矩阵并注明分母，不用占用率推算带宽。
- 采样间隔不均匀或卡异构时说明加权方法；没有有效资源采集仍保留必需矩阵，填n.a.并明确缺口，不能填0或猜测。

`未测`与`已测但指标不可验证(n.a.)`不同，真0保留为0。附原始数据、来源、完整配置、指标单位、分母、失败比例及缓存条件。功能题追加逐题结果与场景汇总，不硬塞进并发矩阵。Excel生成使用目标环境可用的Spreadsheets技能；不可用时采用受支持的xlsx生成库，交付前检查文件可读、数值/公式与布局。
