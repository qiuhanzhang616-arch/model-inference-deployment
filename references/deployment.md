# Standard 部署与启动排障

## 产物与兼容性

- 分清完整 GLM 与 Flash；仓库名字相似不证明架构、量化或镜像兼容。ModelScope 模型仓库提供权重，不是容器镜像。
- 优先用户指定来源的权重与匹配硬件的官方镜像，不默认重建镜像。先核对实际硬件 A2/A3、CPU 架构、CANN/驱动、推理框架版本、模型架构、量化与 MTP 支持；vLLM-Ascend或SGLang的选择以当时官方兼容信息与实际验证为准。
- 执行时查所选模型/硬件的官方部署文档及权重仓库revision，记录来源URL。不绑定某个模型版本或第三方量化仓库；模型仓库可访问不代表权重已下载或获得官方量化背书。
- 下载到独立新目录。检查空间、仓库 revision、文件清单、分片数、safetensors 索引引用完整性、config/tokenizer/generation 配置、大小及来源提供的校验值。自行算 hash 仅证明文件稳定，不能代替可信来源校验。验证后原子写完成标记。
- 镜像记录官方源 URL/tag、平台 manifest digest、目标镜像地址和摘要。私库转存不等于自制；比较对应平台的内容摘要，勿混淆多架构索引与子 manifest。记录运行容器实际 imageID；只有 tag 时注明限制。
- 启动脚本、权重只读挂载，运行日志与 handoff 读写挂载。依赖修改若确需重建，先说明官方镜像不足之处；保存基镜像摘要、补丁、构建记录和回滚，不悄悄 pip 覆盖受保护环境。

## Standard 不能照抄 Lite Server

1. 读平台实际注入的角色、实例标识、POD_IP、设备和网络信息；不要猜 Lite Server 的 rank/environment变量在 Standard 上存在。
2. POD_IP 必须对应本容器唯一可用接口，并能本地 bind。GLOO/HCCL/VLLM 等地址和 NIC 按该接口设置；RDMA/设备网络与容器 IP 的关系须实测，不硬编码历史 IP。
3. 首选已验证的 Standard 元数据发现。如元数据缺失，可使用隔离的 SFS rendezvous，但必须有 deployment/cohort/run namespace、当前实例标识、唯一成员和超时。
4. 拒绝陈旧注册、其他部署/实例、重复 IP、重复 rank、成员缺失/超额、本地设备数不符。主节点来自明确角色，不按 IP 排序猜。不要伪造或覆盖全局 rank table。
5. 所有角色用同一版本脚本和权重 hash。master API 与 headless worker 端口、连通性、DP rank 范围一致。SFS 注册原子写入，失败退出并保留日志，不能无限等候。

## 拓扑与资源

- UI“多角色部署”只是编排形式，不等于 PD 分离。DP 副本各自同时执行 prefill/decode 是混部；真正 PD 要有不同 P/D 引擎、KV connector、路由和实际 KV 传输证据。
- DP4×TP8 且每 DP 一组8卡，是32卡混部示例；DP2×TP8是16卡。跨节点 PP/TP 和 EP 另核实映射，EP 不能被不加分析地再次乘作额外卡数。
- PD 卡数按每个 P/D 角色的副本×每副本设备数求和。卡数上限取本次用户要求，不把历史扩容授权压过最新的固定卡数约束。
- 资源盘点列出节点总卡、分配/预留/空闲、所属任务/Pod/服务。停止前精确识别所有者；不按“看起来空闲”删除系统任务。停止后确认旧 Pod 退出、调度预留释放，不能只看服务卡片。
- 资源紧张时滚动升级的 surge 会申请额外卡。若用户允许中断，可评估surge=0、最大不可用100%以及按平台语义调整副本重建策略。先核对影响范围，不改健康探针掩盖失败；也不能把某开关直接当作所有卡死的已证根因。

## 启动成功的证据链

依次区分：已准备 → 已提交 → 已调度 → 容器启动 → 权重加载 → 分布式初始化 → KV分配/图捕获结束 → HTTP健康 → 指定后端真实生成 → 正式测试通过。

每次重建后采集新 cohort 的全部角色 hostname/IP、时间戳、进程 argv、初始化配置、imageID、TP/DP/MTP、上下文、KV能力和首个成功响应。旧日志与旧 proof 不用于新实例。权重进度仍前进时不要随意重启；无进展时按日志定位最早失败阶段。

| 现象 | 最小定位路径 |
|---|---|
| 长期 Pending | 节点卡归属、配额、亲和性、预留、surge、旧副本与重建循环 |
| 等 peer/rank table | 实际角色/注入变量、rendezvous namespace、成员唯一性、端口可达性 |
| Transformers fallback、架构 KeyError | 是否误用完整模型旧镜像、包覆盖、模型配置与镜像兼容 |
| 引擎能起但长请求排队，KV利用率为0 | 调度/admission拒绝计数、实际KV组/块布局；不等同显存耗尽 |
| PD transfer 报 block size 不符 | 检查源/目标 block layout、remote block size、connector与内核支持，按实际日志确认不匹配值 |
| EngineDead/图编译异常 | 保存各rank首错，离线核对图模式，再做隔离 eager/graph A/B |
| 600s/3600s附近失败 | 分层看客户端、LiteLLM、反代、ModelArts、引擎超时和完整SSE元数据；不能仅凭504宣布NPU容量不足 |

只修当前证据支持的原因。不要声称某规模PD成功，除非对应实际卡数的运行、传输和端到端验收都有记录。
